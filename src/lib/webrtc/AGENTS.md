# Call stability

- Queue local offers until signaling is stable; never force-release an in-flight lock or count delayed mesh answers as failures, because competing negotiations cause reconnect loops.
- Received camera/mic streams hold one live track per kind and change identity on replacement; ignore obsolete connection events so playback never binds to stale recovery tracks.
- Automated health checks respect active negotiation, disconnect grace, recovery ownership and intentional mute; keep manual resync explicit so routine sweeps do not tear down working calls.
- Calls carry audio only over WebRTC with a community TURN last-resort relay; never mute received RTP or push audio frames over the data mesh, because that starved signaling and silenced both paths. Re-offer missing inbound tracks only for confirmed microphone senders; unknown/listen-only peers are not failures.
- A join-room from a peer whose call is already connected is a re-announce (mesh link reopened, silence revival): never re-offer, or both sides renegotiate at once whenever a newcomer reshuffles the mesh.
- Preserve silent/local/explicit departures end-to-end: mesh silence leaves active media and recovery in control, with bounded recovery permission after room eviction; explicit leave or local mesh shutdown still closes calls. Room silence allows a minute and ICE disconnects get twenty seconds before recovery, because mobile timers and network transitions need grace.
- Glare on a call's very first negotiation: the polite side answers from a fresh connection instead of rolling back. Rolled-back upfront transceivers keep no mid, and stopping them leaves them pending forever, which made the browser raise negotiationneeded after every answer (an endless offer/answer loop). Later renegotiation glare still rolls back on the same connection.
